# decision — Section 6·7

| 강 | 대상 | 판정 | 근거 |
|---|---|---|---|
| 6-2 | 멱등 키에 SQS MessageId 사용 | reject | 재발행·재처리 중복은 MessageId 가 달라 못 막는다 |
| 6-2 | Claude Code 구현(조건부 쓰기 선점) | edit | 상태(`IN_PROGRESS`/`COMPLETED`)·선점 만료·발송사 결과 조회를 추가해 채택. 선점 뒤 중단·응답 타임아웃 테스트 통과 |
| 6-3 | Claude Code 구현을 순차·동시 테스트로 그대로 검증 | accept | 촬영 때 실제 세션 결과로 채운다 |
| 6-3 | 비교용으로 준비한 "조회 후 저장" 구현 | 비교 기준 | 순차 PASSED, 동시 FAILED `expected: <1> but was: <2>`. 조회와 저장 사이의 틈 |
| 6-4 | 부분 배치 실패 보고 켜기 | accept | 끔: 정상 메시지도 수신 3회. 켬: 실패 메시지만 3회 |
| 6-5 | 전체 재처리만 쓰기 | edit | 원인이 다른 메시지가 섞이면 선별 재처리를 먼저 쓴다 |
| 7-2 | 테넌트 분리를 FIFO 큐 + `MessageGroupId` 로 | reject | FIFO 는 그룹 안 순서를 지키려고 같은 그룹의 다음 메시지를 앞 메시지가 끝날 때까지 묶어 둔다. 발송은 순서가 필요 없고 대량 테넌트 하나가 한 그룹이 되면 그 테넌트가 오히려 느려진다. Standard 큐의 fair queue(`MessageGroupId`)로 대체(ADR 0003) |

> 6-3 의 "조회 후 저장" 은 AI 가 낸 코드가 아니라 비교용으로 준비한 구현이다. AI 가 낸 코드도 같은 테스트로 검증한다.
